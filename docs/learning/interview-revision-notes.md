## 重点纠错与澄清

| 位置 | 原来容易产生的理解 | 修订后的准确说法 |
|---|---|---|
| Q010 | 提交后都要“释放预扣” | 下单成功后保留占位；取消或关单提交后释放；下单回滚时补回预扣 |
| Q010 | 所有 afterCommit 异常都会直接向客户端传播 | 一般异常不能撤销已提交事务；本项目 MQ 发送异常在发送方法中已捕获 |
| Q042 | Spring AUTO 等于消息一到就确认 | AUTO 是容器管理处理后的确认，区别于协议层不等待处理的自动确认，也不等于手写 ACK |
| Q042 | publisher confirm 表示消息已消费或一定路由到队列 | confirm 不代表业务消费完成；不可路由消息需单独处理 return 等机制 |
| Q052 | 数据库 SQL 执行成功就代表已经提交 | 点赞事务里的 Redis 异常可能导致数据库回滚；反方向仍可能留下缓存残留 |
| Q002 | 列表 available=true 就保证可以下单 | 列表检查场次库存大于零且资源未占用，不会预留名额，也不保证一次选择的多个资源总量足够 |
| Q008、J37 | private 或自调用就意味着完全没有事务 | 自调用不触发新的代理增强，但内部操作可能仍参与外层事务 |
| J15 | 所有 toList 都是可随便增删的 ArrayList | Stream.toList 不可修改；Collectors.toList 不承诺具体可修改性 |
| J43 | 按 Java 实体名猜测 SQL 表名 | ReserveSession 映射的实际表是 `session`，条件扣减 SQL 标为改进示例 |
| Q059、Q069、Q072 | 使用 Lua/Redisson 就可以宣称高并发成果 | 机制实现与并发正确性、容量测试分别说明，不编造指标 |

表中有些是纠正原文歧义，有些是补充原先遗漏的限制，不代表每个原答案都完全错误。其他风险继续参考 [当前实现边界](12-implementation-boundaries.md)。

## 校验怎样理解

维护工具检查 JSON 结构、编号、源码符号、本地链接、Markdown 代码围栏以及生成阅读版是否与题库一致。工具测试覆盖增删改查、备份、格式错误与对话段落保留；另核对原有学习状态和个人笔记未丢失。

这些校验不检查业务系统运行结果，不证明所有外部链接永久有效，也不代表问答中提出的改进已经实现。原理需要结合官方来源、源码及后续实验继续维护。
