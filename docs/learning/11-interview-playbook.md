# 11 项目介绍与模拟追问

## 90 秒介绍示例

VenuePass 是一个场馆预约与核销后端，资源既可以是座位，也可以是球场或房间。用户先选择场次和资源，再下单、模拟支付、凭码核销，核销后可以发布点评，经管理员审核后展示。系统区分普通用户、管理员和核销员。

项目使用 Spring Boot、MyBatis-Plus、MySQL。Redis 用于下单防重复提交、库存预扣、场馆缓存和排行榜；Lua 在 Redis 内原子校验数量和资源占位；Redisson 按场次加资源 ID 协调锁，MySQL 唯一约束阻止重复有效占位。超时订单提供 RabbitMQ TTL + 死信队列处理代码，并保留定时扫描。

我重点理解的是各层保证的边界：数据库事务不覆盖 Redis 和消息，锁粒度不一定覆盖共享库存总量，角色权限也不等于数据归属权限。当前 MQ 真实环境故障测试和部分并发场景仍需要验证，我会用实验记录说明自己实际完成的部分。

根据自己的真实工作调整“负责/实现/学习”的表述，不把参考实现或工具协助内容说成从未发生过的经历。

## 回答骨架

每题先回答结论，然后说本项目的类/方法与执行顺序，再说失败窗口、验证办法和取舍。控制首轮在 60-90 秒，给面试官留追问入口。

示例：“Lua 能保证本脚本中的资源检查、数量判断、预扣和占位不被其他命令穿插。它不能回滚 MySQL，也不承诺运行时错误前的写入自动恢复。项目用 DB 事务结束回调做普通回滚补偿，但进程退出后还需对账或持久补偿。”

## 六条递进追问链

### 预约库存

Q020 Lua 为什么原子 -> Q024 为什么还需要锁 -> Q012 不同座位为何仍可能丢更新 -> Q023 预扣成功进程退出怎么办 -> Q026 Cluster 两个 key 不同槽怎么办。

应能在白板上画出竞争时序与数据库条件 SQL，并指出当前代码尚未覆盖的部分。只回答“Redis 单线程所以没问题”不合格。

### 登录与幂等

Q033 两种 token 区别 -> Q035 用户超时后重试 -> Q036 token 如何绑定用户 -> Q037 登录用户能否操作别人订单 -> Q038 禁用用户后旧 JWT 怎么办。

应能识别身份、动作、防重和对象权限是不同问题。

### 状态与事务

Q011 状态机为何不等于并发安全 -> Q009 DB 回滚是否恢复 Redis -> Q010 afterCommit 时机 -> Q044 Outbox 能解决什么 -> Q048 审计日志是否能代表最终提交。

应能给出双方都读到 PENDING 的并发时序，并说明所有状态写入方必须配合。

### 缓存

Q029 空值为什么防穿透 -> Q030 互斥如何重建 -> Q031 先改 DB 再删缓存仍哪里不一致 -> Q032 Redis 故障是否直连 DB -> Q069 怎么证明缓存有效。

应能画旧值回填时序和给出观测指标；不能把随机 TTL 描述为解决所有宕机。

### MQ

Q041 延迟消息里是什么 -> Q042 confirm 与 ACK -> Q043 重复消费 -> Q045 到期是否精确 -> Q046 多实例扫描 -> Q047 积压排障。

应明确 MQ 是未来检查的触发，业务事实在 DB。没有真实 broker 联调证据就如实说明。

### 横切功能与工程

Q049 ThreadLocal 泄漏 -> Q050 INCR/EXPIRE 原子性 -> Q051 fail-open 与代理 IP -> Q055 通知为何仍需 DB -> Q056 CONNECT 是否足够授权 -> Q060 故障如何定位。

应能说出副作用、线程复用、可信边界和持久性，不只背注解。

## 高频误区纠正表

| 不严谨的说法 | 更准确的说法 |
|---|---|
| 项目已经支持高并发 | 实现了并发控制机制，承载能力需用可复核压测说明 |
| Redis 与数据库强一致 | 当前有预扣与回调补偿，仍有跨系统失败窗口 |
| token 是幂等返回同一订单 | 当前一次性令牌拒绝重复，不保存首次订单结果 |
| 有状态机就不会状态竞争 | 状态校验还需配合条件更新和影响行数 |
| 有 Spring Security 就无越权 | 路由角色和对象归属需分别校验 |
| durable 队列确保消息不丢 | 还需确认发送、持久消息、消费与故障恢复语义 |
| TTL 到期订单一定秒级关闭 | TTL 是触发，执行受积压、调度和依赖耗时影响 |
| 已使用 MyBatis-Plus 乐观锁 | 当前需看是否有版本字段与拦截器，不能仅看依赖 |
| 用了 Java 21 就有虚拟线程 | 当前未配置或验证该能力 |
